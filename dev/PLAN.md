# 구조 변경 + 멀티플레이 계획 (체크리스트)

목표: 지금의 「파일을 이어 붙이고 이름을 모두 같이 쓰는」 구조를 **일반적인 게임 개발 구조(모듈 import/export)** 로 단계적으로 바꾸고,
그 위에 **코어키퍼 방식 멀티플레이**(같은 세계에서 각자 따로 움직이기)를 얹어요. 끝나면 주변 사람들에게 배포해요.

- 한 단계씩 진행하고, **단계마다 게임은 그대로 동작**해야 해요 (비교 테스트 + 전체 테스트 통과 → 배포).
- 게임 동작·밸런스·그림·조작감은 바꾸지 않아요. 멀티플레이 단계(B)에서 새로 생기는 것만 예외.
- 단계를 마치면 이 파일의 체크 표시와 「진행 상황」을 갱신해 같이 커밋해요.
- 계획을 정한 날: 2026-10-12 (v64 직후). 예상: A 약 45~70시간, B 약 40~85시간.

## 멀티플레이 방식 (정한 것)

- **방장(호스트) 방식**: 방장의 게임이 세계를 계산하고 저장해요. 친구는 방 코드로 들어와 「하려는 행동」(명령)만 보내고, 방장이 결과를 나눠 줘요.
- **연결**: 브라우저끼리 직접 연결(WebRTC). 처음 연결을 맺어 주는 작은 서비스만 따로 필요 (13단계에서 고르기).
- **캐릭터는 내 기기, 세계는 방장 기기**에 저장 (코어키퍼처럼 내 캐릭터로 여러 세계에 들어감).
- **각자 따로 움직임**: 플레이어마다 주변 구역이 살아 있고(몬스터·작물·기계), 친구에게는 그 친구 주변 변화만 보내요.
- 처음 인원 2~4명. 전용 서버(방장 없이 늘 켜진 세계)는 나중에 선택.
- 나중에 정할 것: 최대 인원, 연결 서비스, 방장이 나갈 때 처리, 친구가 방장 세계에서 얻은 물건 규칙.

## 목표 폴더 구조 (dev/src/js/)

| 폴더 | 맡은 일 |
|---|---|
| `engine/` | 난수(게임 결과용·효과용 따로), 노이즈, 색, 소리, 캔버스 붓, 공통 도구 |
| `data/` | 아이템·레시피·물체·벽·보스·퀘스트·팁 — 순수 데이터 (밸런스는 여기만) |
| `art/` | 캐릭터·몬스터·타일·아이콘 그림 만들기, 손그림 |
| `save/` | 세계 상태·캐릭터 상태, 저장/불러오기, 옛 세이브 보정, 백업·클라우드 |
| `world/` | 지도 만들기, 충돌·이동, 땅 파기·놓기, 숨은 방 |
| `sim/` | 게임 규칙: 명령 처리, 개체(플레이어·몬스터·보스·펫), 시스템(전투·농사·요리·제작·회로·생존·자동화·퀘스트), 매 프레임 진행 |
| `net/` | 멀티플레이: 방 만들기·들어가기, 명령·상태 주고받기 |
| `render/` | 카메라·세계·빛·지도 그리기 (내 플레이어 기준) |
| `ui/` | HUD·창·창 안 버튼·끌어 옮기기·입력 → 명령 만들기 |
| `main.js` | 시작과 게임 루프 |

규칙(sim)은 화면·소리를 직접 부르지 않고 「사건」만 남겨요. 화면(render·ui)은 규칙 상태를 읽기만 해요. 이것이 멀티플레이의 바탕이에요.

## 단계

### A. 구조 변경 + 멀티플레이 준비

- [x] **0. 준비** — `build.py`가 import/export를 이해 (옛 파일과 섞여도 됨, 결과는 지금처럼 한 파일 `index.html`).
  확인: 가져오는 파일이 있는지, 내보내는 이름인지, 맨 위 이름이 겹치는지, 다른 모듈 이름을 import 없이 쓰는지. 테스트 통로(`window.__T`)는 이름이 그대로라 그대로 써요.
- [x] **1. 기초 도구** — `core.js` → `engine/`(util·random·canvas·audio·effects) + `sim/drops.js`. 난수를 한곳에서: 게임 결과용 `rand()`(나중에 방장만 굴림)과 보이기용 `fxRand()`로 나눔 (게임 전체 128곳 분류, `Math.random` 직접 쓰기는 `build.py`가 막음).
  남은 것: `soundOn`(state.js)·`MKDEF`(art/world.js가 바꿈)처럼 옛 파일이 모듈 값을 읽고 바꾸는 이름 — 그 파일들을 옮길 때 설정 함수로.
- [x] **2. 게임 데이터** — 데이터만 `data/` 모듈 10개로: `items`·`rpg-nature`·`circuits-regions`·`quests`·`farming-cooking`·`gear-animals`·`deep-survival`·`automation-tiers`·`controls` (+ 보스·재도전 보상·숨은 방·내구도·분해 표도 모음).
  각 데이터 파일은 같은 이름의 규칙 파일 바로 앞에 와서 실행 순서가 예전과 같아요 (「지형 재료 2배」 등 순서에 기대는 보정도 그대로). 비교 테스트(데이터 70여 개 표·그림 지문·옛 세이브)가 한 글자도 안 바뀜.
  섞여 있던 줄(아이템 + 아이콘)은 둘로 나눠 아이콘은 규칙 파일에 남김 — 아이콘 등록 순서까지 그대로.
  남은 것: 무기·장식·자연 꾸미기 표(`WEAPONS`·`DECOR`·`NATURE`·`GEAR2`·`ROOM_DECO_DEF`) 안에 그림(아이콘·스프라이트)이 함께 들어 있음 → 3단계에서 그림을 떼어 내요.
- [x] **3. 그림** — `art/` 3개 파일을 모듈로, 규칙 파일 10곳에 흩어져 있던 아이콘·물체 그림·몬스터 그림을 `art/content.js` 하나로 모음 (이제 `ICON`·`OSPR`을 넣는 곳은 `art/`뿐).
  데이터 표 안의 그림도 떼어 냄: `WEAPONS`·`UNIQ`·`GEAR2`의 아이콘 → `WEAPON_ICON`·`UNIQ_ICON`·`GEAR2_ICON`, `DECOR`·`NATURE`·`ROOM_DECO_DEF`의 그림 → `DECOR_SPR`·`NATURE_SPR`·`ROOM_DECO_SPR`.
  비교 기록 갱신 두 번: 아이콘 등록 순서(`SPR.item` 키 순서만, 그림 304장 모두 같음) · 표에서 그림 칸이 빠짐(그 밖의 값 모두 같음).
  빠뜨렸던 데이터 하나(보스 조각상 `SUMMON`, game/combat.js)도 `data/quests.js`로. `build.py`: 뒤 파일에서 가져오기 허용, 손그림 표시(`/*@@ART*/`)는 따로 줄에.
- [x] **4. 상태·저장** — `save/` 3개 파일을 모듈로. 세이브를 **세계**(방장 기기·같이 씀) · **캐릭터**(내 기기·들고 다님) · **세계 안 플레이어별**로 나누는 `splitSave`·`joinSave`·`serializeWorld`·`serializeChar`·`deserializeParts` (`save/state.js`).

  - 계획에서 바꾼 것: 메모리 속 `G`를 세계·캐릭터로 나누는 일은 **8단계(플레이어 여러 명)에서 함께** 해요 — `G.p`를 플레이어 목록으로 바꿀 때 한 번에 하는 게 두 번 고치지 않는 길이에요.
  - 남은 것: 옛 파일이 `save/state.js`의 값을 직접 바꾸는 이름(`G`·`shake`·`paused`·`started`·`soundOn` …) — 그 파일들을 모듈로 옮길 때 설정 함수로. 캐릭터만 따로 옛 버전 보정이 필요해지면(친구 세계로 갈 때) 캐릭터 쪽 버전 표시를 13단계에서.

## 진행하는 동안 지킬 것

- **내용 추가**(아이템·레시피·그림·밸런스)는 언제든 괜찮아요. 이미 옮긴 부분은 새 구조로, 아직이면 지금 구조로.
- **새 게임 시스템**(새 규칙·동작)은 8단계 뒤부터 괜찮아요 — 사건(`emit`)·명령(`defineCmd`)·매 프레임 순서표(`onFrame`)·플레이어 여럿(`withPlayer`) 규칙대로 만들어요 (8단계 끝, 2026-10-12).
- 모듈 규칙: `import { a, b } from './x.js'` (같은 이름 그대로, `as`·`default` 없음), `export function/const/let/class`, `export { a, b }`.
  아직 모듈이 아닌 파일의 이름은 import 없이 그대로 써요 (옮기면 import로 바꿈). 모듈의 이름은 반드시 import.
  - 묶을 때 이름은 그대로 한 곳에 모여요. 그래서 다른 파일과 맨 위 이름이 겹치면 안 돼요 (`build.py`가 알려 줌).
  - 다른 모듈이 내보내는 이름과 같은 이름의 지역 변수를 쓰면 `build.py`가 import하라고 잘못 알릴 수 있어요 → 지역 변수 이름을 바꿔요.
- 옮긴 파일 순서도 `shell.html`의 `@include` 순서를 따라요. 뒤 파일에서 가져오는 것도 되지만(서로 부르는 함수 등), 맨 위에서 바로 쓰는 이름은 앞 파일에 있어야 해요 (아니면 게임이 켜지자마자 오류 — 비교 테스트가 잡아요). 맨 위에서 바로 실행되는 줄의 순서가 바뀌지 않게 조심.
