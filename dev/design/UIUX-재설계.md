# UI/UX 전면 재설계 — 방향 및 설계 범위

- 상태: **【확정 기획】 재설계 우선순위·대상 플랫폼 / 【검토 중】 화면 구성과 상호작용**
- 갱신: 2026-10-14
- 현재 단계: **전체 IA와 플레이 화면(HUD)의 기획·설계** (코드 구현 일정 미확정)
- 코드 구현 요청서가 아닌 기획 작업 문서

## 목표

모바일 **세로 화면**에서 탐험·전투·건축 흐름을 가로막지 않으면서 정보를 읽기 쉽게 만들고 조작 부담을 낮춘다. 기존 기능의 정보 구조를 우선 개선하고, 장기적으로 들어올 NPC·스토리 인터랙션을 수용할 공간을 확보한다.

## 확인된 범위와 제약

- 【구현】 게임은 Canvas 월드와 HTML/CSS HUD·패널을 사용한다. PC/모바일 조작은 별도 검증이 필요하다.
- 【구현】 현재 제작, 인벤토리, 건축, 퀘스트, 상호작용 등 여러 UI가 존재한다. 자세한 실제 구현은 `dev/src/js/ui/`, `dev/src/style.css`, 최신 게임 현황 문서를 우선한다.
- 【확정 기획】 **제작 화면만 수정하지 않고 전체 UI/UX를 재설계**한다.
- 【확정 기획】 모바일 세로 화면을 우선 고려하되 PC 플레이의 조작성도 배제하지 않는다.
- 【확정 기획】 불필요한 터치 횟수, 정보 과밀, 작은 알림, 장면 가림을 줄이는 것을 목표로 한다.
- 【검토 중】 기존 HUD 레이아웃을 유지할지, 탐색·전투·건축 맥락에 따라 다른 구조를 사용할지.

## 설계 진행 순서

1. **전체 IA:** 상시 HUD / 일시 패널 / 전체 화면 / 상황별 상호작용, 기능 진입 경로와 정보 우선순위 정리.
2. **HUD:** 체력·기력·상태, 현재 목표, 방향 안내, 행동 버튼, 단축칸, 알림의 배치·표시 조건.
3. **주요 화면:** 인벤토리·장비, 제작, 건축, 지도, 퀘스트, 캐릭터 정보, 설정.
4. **공통 패턴:** 탭·필터·목록/격자·상세 정보·선택/취소·제작 실행·팝업·알림·상태 피드백.
5. **미래 확장 슬롯:** NPC 대화, 이야기/도전 퀘스트 및 향후 메인 스토리·시스템 안내, 발견 기록을 IA에 반영하되 세부 콘텐츠가 확정된 것으로 간주하지 않는다.
6. **검증:** 실제 모바일 화면에서 가독성·엄지손가락 도달성·게임 화면 가림·제작/건축 완료까지 입력 횟수와 오류를 확인한다.

## 멀티플레이 기반 UX 설계 제약 (2026-10-14 Claude 기술 검토 반영)

### 1. 창 사용 중에도 세계가 진행되는 상황

- 【현재 구현】 `ui/panels.js`의 `openPanel()`은 `setPaused(true)`를 호출하고, `main.js`는 일시정지 중 `update(dt)` 대신 `pausedTick(dt)`을 사용한다. 즉, 현재 싱글 화면에서는 일반 패널 사용 시 세계가 멈춘다.
- 【확정 기획 · 2026-10-14】 **싱글플레이와 멀티플레이 모두 플레이 도중 가방·제작·지도·퀘스트·설정 메뉴와 NPC 대화창을 열어도 세계는 일시정지하지 않는다.** 세계 시간, 몬스터의 이동·공격 등 게임 진행이 계속된다. 멀티플레이에서도 다른 사용자의 행동을 정지시켜서는 안 된다. 제목 화면이나 로딩처럼 플레이가 진행 중이지 않은 상태의 동작을 이 규칙이 새로 정의하는 것은 아니다.
- 【설계 요구】 인벤토리·제작·건축 관련 패널·지도·퀘스트·NPC 대화창을 연 상태에서 적의 접근과 피격을 알아차릴 수 있도록 한다. 화면을 지나치게 가리지 않고, 빠른 닫기/복귀 동선, 상태·피격 피드백, 위험 중 조작 부담을 검토한다.
- 【확정 기획】 싱글/멀티 구분 없이 **플레이 중 메뉴·대화창을 열었다는 이유로 세계를 멈추지 않는다.** 싱글플레이 기존 일시정지 방식은 향후 구현에서 변경해야 한다.
- 【구현 전 주의】 기존 `setPaused(true)` 등 게임 일시정지 동작을 변경할 때는 메뉴·대화창에 의해 입력 초점이 이동한 상태에서 공격·피격·시간 작업·접근성을 검증한다. 이 문서만으로 코드를 수정하지 않는다.
- 【검토 중】 피격 시 열려 있는 창을 유지·축소·자동 닫기 중 어떻게 처리할지, 창을 보고 있는 동안 캐릭터의 이동·방어가 어떻게 가능한지 별도 검증한다. **일시적 무적이나 자동 닫기를 확정한 것은 아니다.**

### 2. 멀티플레이 정보 구조에서 확보할 자리

| UX 항목 | 설계 시 수용할 정보 | 상태 |
|---|---|---|
| 방 만들기·참여 | 방장 시작, 방 코드 입력, 참가 방법 | 【필요 기능】 단계 13부터 |
| 함께 있는 플레이어 | 참가자 수·동료 식별·연결 상태 | 【설계 필요】 세부 배치 미정 |
| 지도 | 동료의 현재 위치·상태 표시 가능성 | 【설계 필요】 공유/개인 탐험 지도 차이 고려 |
| 재접속·연결 끊김 | 끊김 사유·복귀 행동·진행 가능 여부 | 【필요 기능】 단계 14 전후 |
| 방장 이탈 | 세계 세션 중단 등 상황 안내 | 【검토 중】 실제 방장 이탈 처리 규칙 미정 |
| 오류 신고·안내 | 협동 플레이 도움말과 버그 보고 | 【필요 기능】 단계 15 |

모바일 세로 HUD에는 상시 표시할 필수 정보와 상황별 표시 정보의 우선순위를 따로 판단한다. **미확정 멀티플레이 UI가 확정된 HUD 배치안을 뜻하지는 않는다.**

### 3. 알림과 사운드의 수신 대상

- 【현재 구현】 `ui/feedback.js`의 `onlyMe`를 사용하는 주요 알림·소리·창 이벤트는 현재 내 플레이어의 것으로 제한된다.
- 【검토 중】 보스 처치, 퀘스트 달성, 해금, NPC 상호작용과 같이 다른 참가자에게도 의미 있는 사건의 표시 범위.
- 설계 시 각 사건에 **본인 / 관련 동료 / 세계 전체**, 표시 방식(토스트·HUD·기록·효과음), 중복 알림 억제 기준을 함께 적는다.

### 4. 설계와 개발의 경계

- `dev/PLAN.md`의 멀티플레이 12~15단계 실행 순서는 유지한다.
- 지금은 전체 UI/UX **설계 단계**다. 이 절은 `dev/src/`의 코드 변경 지시가 아니다.
- 멀티플레이 기술 구현 중 생길 임시 화면과 향후 최종 HUD/메뉴 디자인을 구분한다.

## 반드시 구분할 설계 항목

| 주제 | 이미 결정한 것 | 현재 미결정 |
|---|---|---|
| HUD | 모바일 세로 기준으로 다시 설계 | 구체적 버튼 위치와 상시 표시 항목 |
| 제작 | 기존 시스템을 고려해 탐색·제작 경험 개선 | 목록/격자, 탭 깊이, 제작 실행 영역의 최종 형태 |
| 건축 | 기존 탐험·전투 플레이를 방해하지 않아야 함 | 자재 탐색 방식, 빠른 배치 인터랙션 |
| 퀘스트 | 자유로운 목표 발견을 방해하지 않아야 함 | 메인/가이드/서브 정보 구조, 추적·표시 방식 |
| NPC·스토리 | 향후 확장에 필요한 UI 영역 고려 | 대화 UI, 호감도·관계·인물 사전의 실제 채택 |

## 설계 검증 질문

- 화면을 열지 않아도 현재 행동에 필요한 정보가 충분한가?
- 상시 HUD가 세계의 시야를 지나치게 가리지 않는가?
- 자주 하는 행동과 드문 행동을 다른 접근 경로로 분리했는가?
- PC·모바일 입력은 의미와 결과가 일관적인가?
- 플레이어가 현재 이야기/도전 퀘스트를 미뤄두고도 탐험·건축을 즐길 수 있는가?
- 새로운 NPC·스토리 시스템이 추가될 때 HUD를 통째로 다시 만드는 상황을 피할 수 있는가?

## 멀티플레이 개발과의 충돌 방지

- 【구현/진행 계획 확인】 `dev/PLAN.md`에 멀티플레이 12~15단계가 다음 개발 작업으로 남아 있다.
- 【확정 기획】 **기획·와이어프레임 작성**은 지금 진행한다. 이 문서는 즉시 `dev/src/` 화면 파일을 수정하라는 지시가 아니다.
- 【검토 중 — 추천】 `ui/`·`style.css` 등 같은 파일을 동시에 크게 고치지 않도록, **멀티플레이 단계가 안정화된 뒤 최종 승인된 UI 변경을 구현**한다.
- 멀티플레이 자체에 필요한 방 만들기/입장 등의 화면은 임시 구현과 최종 UI를 구분해 기술 검토한다.
- UI 설계 단계에서는 향후 협동 플레이에 필요한 참가/초대·플레이어 상태 표시를 IA 확장 요구사항으로 고려하되, 상세 UX는 별도 결정한다.
- 코드 구현 순서는 사용자 확정 전까지 미정이며 `dev/PLAN.md`를 임의 수정하지 않는다.

## Claude 기술 검토 요청 시 확인할 내용

- 실제 UI 진입 지점/패널 구조, CSS 및 이벤트·명령 처리 방식
- 모바일 화면 크기별 오버플로·가림·터치 히트 영역
- 제안된 IA와 기존 제작 장소·아이템·해금 규칙 간 충돌
- 저장 데이터·기존 조작 규칙의 영향과 회귀 테스트 범위

> 화면별 배치·와이어프레임·상호작용이 승인되면 이 문서에 【확정 기획】 섹션으로 추가한다. 이전 대화의 탐색안은 사용자 승인 없이는 확정으로 승격하지 않는다.
