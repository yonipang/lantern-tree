# UI/UX 전면 재설계 — 방향 및 설계 범위

- 상태: **【확정 기획】 재설계 우선순위·대상 플랫폼 / 【검토 중】 화면 구성과 상호작용**
- 갱신: 2026-10-17 (HUD 와이어프레임 v2 결정 추가)
- 현재 단계: **전체 IA와 플레이 화면(HUD)의 기획·설계** (코드 구현 일정 미확정)
- 코드 구현 요청서가 아닌 기획 작업 문서

## 목표

모바일 **세로 화면**에서 탐험·전투·건축 흐름을 가로막지 않으면서 정보를 읽기 쉽게 만들고 조작 부담을 낮춘다. 기존 기능의 정보 구조를 우선 개선하고, 장기적으로 들어올 NPC·스토리 인터랙션을 수용할 공간을 확보한다.

## 확인된 범위와 제약

- 【구현】 게임은 Canvas 월드와 HTML/CSS HUD·패널을 사용한다. PC/모바일 조작은 별도 검증이 필요하다.
- 【구현】 현재 제작, 인벤토리, 건축, 퀘스트, 상호작용 등 여러 UI가 존재한다. 자세한 실제 구현은 `dev/src/js/ui/`, `dev/src/style.css`, 최신 게임 현황 문서를 우선한다.
- 【확정 기획】 **제작 화면만 수정하지 않고 전체 UI/UX를 재설계**한다.
- 【확정 기획】 모바일 세로 화면을 우선 고려하되 PC 플레이의 조작성도 배제하지 않는다.
- 【확정 기획】 불필요한 터치 횟수, 정보 과밀, 작은 알림, 장면 가림을 줄이는 것을 목표로 한다.
- 【검토 중】 기존 HUD 레이아웃을 유지할지, 탐색·전투·건축 맥락에 따라 다른 구조를 사용할지.

## 설계 진행 순서

1. **전체 IA:** 상시 HUD / 일시 패널 / 전체 화면 / 상황별 상호작용, 기능 진입 경로와 정보 우선순위 정리.
2. **HUD:** 체력·기력·상태, 현재 목표, 방향 안내, 행동 버튼, 단축칸, 알림의 배치·표시 조건.
3. **주요 화면:** 인벤토리·장비, 제작, 건축, 지도, 퀘스트, 캐릭터 정보, 설정.
4. **공통 패턴:** 탭·필터·목록/격자·상세 정보·선택/취소·제작 실행·팝업·알림·상태 피드백.
5. **미래 확장 슬롯:** NPC 대화, 이야기/도전 퀘스트 및 향후 메인 스토리·시스템 안내, 발견 기록을 IA에 반영하되 세부 콘텐츠가 확정된 것으로 간주하지 않는다.
6. **검증:** 실제 모바일 화면에서 가독성·엄지손가락 도달성·게임 화면 가림·제작/건축 완료까지 입력 횟수와 오류를 확인한다.

## 멀티플레이 기반 UX 설계 제약 (2026-10-14 Claude 기술 검토 반영)

### 1. 창 사용 중에도 세계가 진행되는 상황

- 【현재 구현】 `ui/panels.js`의 `openPanel()`은 `setPaused(true)`를 호출하고, `main.js`는 일시정지 중 `update(dt)` 대신 `pausedTick(dt)`을 사용한다. 즉, 현재 싱글 화면에서는 일반 패널 사용 시 세계가 멈춘다.
- 【확정 기획 · 2026-10-14】 **싱글플레이와 멀티플레이 모두 플레이 도중 가방·제작·지도·퀘스트·설정 메뉴와 NPC 대화창을 열어도 세계는 일시정지하지 않는다.** 세계 시간, 몬스터의 이동·공격 등 게임 진행이 계속된다. 멀티플레이에서도 다른 사용자의 행동을 정지시켜서는 안 된다. 제목 화면이나 로딩처럼 플레이가 진행 중이지 않은 상태의 동작을 이 규칙이 새로 정의하는 것은 아니다.
- 【설계 요구】 인벤토리·제작·건축 관련 패널·지도·퀘스트·NPC 대화창을 연 상태에서 적의 접근과 피격을 알아차릴 수 있도록 한다. 화면을 지나치게 가리지 않고, 빠른 닫기/복귀 동선, 상태·피격 피드백, 위험 중 조작 부담을 검토한다.
- 【확정 기획】 싱글/멀티 구분 없이 **플레이 중 메뉴·대화창을 열었다는 이유로 세계를 멈추지 않는다.** 싱글플레이 기존 일시정지 방식은 향후 구현에서 변경해야 한다.
- 【구현 전 주의】 기존 `setPaused(true)` 등 게임 일시정지 동작을 변경할 때는 메뉴·대화창에 의해 입력 초점이 이동한 상태에서 공격·피격·시간 작업·접근성을 검증한다. 이 문서만으로 코드를 수정하지 않는다.
- 【검토 중】 피격 시 열려 있는 창을 유지·축소·자동 닫기 중 어떻게 처리할지, 창을 보고 있는 동안 캐릭터의 이동·방어가 어떻게 가능한지 별도 검증한다. **일시적 무적이나 자동 닫기를 확정한 것은 아니다.**

### 2. 멀티플레이 정보 구조에서 확보할 자리

| UX 항목 | 설계 시 수용할 정보 | 상태 |
|---|---|---|
| 방 만들기·참여 | 방장 시작, 방 코드 입력, 참가 방법 | 【필요 기능】 단계 13부터 |
| 함께 있는 플레이어 | 참가자 수·동료 식별·연결 상태 | 【설계 필요】 세부 배치 미정 |
| 지도 | 동료의 현재 위치·상태 표시 가능성 | 【설계 필요】 공유/개인 탐험 지도 차이 고려 |
| 재접속·연결 끊김 | 끊김 사유·복귀 행동·진행 가능 여부 | 【필요 기능】 단계 14 전후 |
| 방장 이탈 | 세계 세션 중단 등 상황 안내 | 【검토 중】 실제 방장 이탈 처리 규칙 미정 |
| 오류 신고·안내 | 협동 플레이 도움말과 버그 보고 | 【필요 기능】 단계 15 |

모바일 세로 HUD에는 상시 표시할 필수 정보와 상황별 표시 정보의 우선순위를 따로 판단한다. **미확정 멀티플레이 UI가 확정된 HUD 배치안을 뜻하지는 않는다.**

### 3. 알림과 사운드의 수신 대상

- 【현재 구현】 `ui/feedback.js`의 `onlyMe`를 사용하는 주요 알림·소리·창 이벤트는 현재 내 플레이어의 것으로 제한된다.
- 【검토 중】 보스 처치, 퀘스트 달성, 해금, NPC 상호작용과 같이 다른 참가자에게도 의미 있는 사건의 표시 범위.
- 설계 시 각 사건에 **본인 / 관련 동료 / 세계 전체**, 표시 방식(토스트·HUD·기록·효과음), 중복 알림 억제 기준을 함께 적는다.

### 4. 설계와 개발의 경계

- `dev/PLAN.md`의 멀티플레이 12~15단계 실행 순서는 유지한다.
- 지금은 전체 UI/UX **설계 단계**다. 이 절은 `dev/src/`의 코드 변경 지시가 아니다.
- 멀티플레이 기술 구현 중 생길 임시 화면과 향후 최종 HUD/메뉴 디자인을 구분한다.

## 캐릭터 화면 재설계 — 장비 · 스킬 · 빛/등불 (2026-10-14)

### 사용자 결정과 적용 범위
- **【확정 기획 · 방향】 이전에 독립적으로 존재했다가 v48에 가방으로 합쳐진 '장비창'을 다시 독립적인 캐릭터 화면으로 복원한다.** 기존 가방 속 장비 4칸의 데이터를 복원/초기화하는 것이 아니라, **UI의 진입 경로와 배치를 재구성**하는 결정이다.
- **【확정 기획 · 정보 구조 방향】 코어 키퍼의 캐릭터 화면처럼 하나의 캐릭터 성장 화면에서 세 영역을 전환한다:** ① 장비 ② 스킬 ③ 보스의 영혼에 대응할 수 있는 세계관 고유 영역. **셋째 영역의 '영혼'을 '등불'로 부를지, '빛/빛의 기억/축복'으로 부를지 및 실제 기능은 【검토 중】**이다.
- 【확정 기획】 전체 UI/UX 재설계 및 모바일 세로 화면 우선, 플레이 중 메뉴를 열어도 세계 진행 유지 원칙과 함께 설계한다.
- **【구현 현황 · 2026-10-14 main】** `ui/panels.js`의 `openPanel('equip')`은 `inv`로 바꾸며, 가방 렌더링 상단에 `eqRowHTML()` 장비 행이 포함된다. `sim/gear.js`의 실제 장비 상태는 `body/head/neck/ring` 4슬롯이다. 무기 전용 장착칸은 v48에 없어졌다. 별도 '능력' 패널에서 4종 능력치와 16개 스킬을 관리하며 액티브 스킬은 2칸에 배치한다. **셋째 영역에 대응하는 보스 영혼/캐릭터 등불 능력 시스템은 확인된 구현 목록에 없다.**

### 【검토 중 · 추천】 정보 구조와 책임 분리
| 화면/탭 | 핵심 목표 | 기존 데이터 및 영향 |
|---|---|---|
| 장비 | 캐릭터 프리뷰를 중심으로 현재 착용 효과를 이해하고 착용/교체하기 | 기존 옷·머리·목걸이·반지 4슬롯 유지. 가방의 '장비' 카테고리로 후보 아이템 선택; 장착과 소지 아이템은 동일 상태를 참조 |
| 스킬 | 레벨·성장 포인트·능력치 4종·일반/마법/활/생활 스킬·액티브 스킬 2칸 관리 | 기존 레벨 최대 30, 스킬 16종/각 3단계, 스킬 포인트·무료 재분배·기존 효과를 임의 변경하지 않음 |
| 빛/등불(가칭) | 코어 키퍼 '영혼'과 같은 '특별한 발견·해금'의 공간을 등불나무 세계관에 맞게 제공할 수 있을지 검증 | 현재 등불나무에 심는 빛씨앗 0~5개는 세계 진행, 밝기·안전 지역·축복·엔딩에 연결됨. **즉시 '개인 영혼'으로 치환하거나 전투 버프를 신설하지 않음** |

**초기 IA 추천:** 메인 메뉴/기존 '능력' 진입을 중복하지 않고 '캐릭터'로 통합, 탭은 `장비 / 스킬 / 빛(가칭)`. 일반 소지품·단축칸·도구 주머니·정렬·상자 이동은 **가방**에 남긴다. 장비 탭에서 슬롯 선택 → 해당 슬롯에 착용 가능한 가방 물품만 필터링 → 효과 비교 → 교체/해제. PC에서는 후보 목록을 옆에, 모바일에서는 같은 화면 내 하단 영역/보조 시트에 표시하는 방식 검토. 장비창은 가방 전체를 복제하지 않는다.

**스킬 탭 추천:** 상단에 레벨·남은 능력치/스킬 포인트를 표시하고, 아래에 능력치 4종 및 스킬 카테고리를 구분한다. 현재 액티브 스킬 2칸의 설정을 한 화면에서 관리하되, 새로운 스킬 트리·포인트 경제를 승인 없이 추가하지 않는다.

**셋째 탭의 개념 분리:** 코어 키퍼의 영혼은 보스 개인 보상 능력이고, 등불나무의 기존 빛씨앗은 '세계의 등불나무 성장'이다. 공통으로 '빛'을 쓰되 **세계 공통 진행 정보**와 미래에 도입할 수 있는 **캐릭터 개인의 발견/축복 능력**은 저장·보상·전투 효과를 분리해야 한다. 처음에는 기존 세계 진행을 정보로 보여주는 것만으로 탭의 사용 가치를 검증할 수 있으나, 개인 영혼 능력의 도입·획득 조건·효과는 **승인 전 미구현/검토 중**이다. 기존 액티브 '등불 치유'와도 기능을 중복시키지 않는다.

### 【검토 중】 중요한 상세 결정과 위험
1. **장비 슬롯 추가 여부:** 코어 키퍼의 슬롯 개수를 모방하지 않는다. 특히 '무기 장착칸'을 다시 만들면 현재 '든 무기 → 마지막 무기 → 가방 속 가장 센 무기 → 주먹' 자동 선택과 충돌한다. 우선 4칸 유지 권장; 무기는 표시만 할지 별도 결정을 받는다.
2. **프리셋(I·II·III):** 화면 속 장비 세트 전환의 필요성·저장 범위·빈 가방/중복 장비·멀티플레이 동기화 비용 검토 후 선택 도입. 아직 확정 아님.
3. **세 번째 탭:** 이름(등불/빛/기억 등), 월드 진행 요약인지 개인별 보스 능력인지, 탭 개방 시점, 빈 상태 표시, 능력 온/오프, 저장 소유권(세계 공통/캐릭터 소유/세계 안 플레이어별)을 결정해야 한다.
4. **모바일 세로 레이아웃:** 상단 탭 3개, 장비 탭의 캐릭터 프리뷰와 4슬롯, 선택 장비 상세/비교, 스킬 카테고리 및 포인트 배치를 화면 높이 별로 검증한다. 아이콘만 두고 의미가 숨겨지는 탭, 너무 작은 슬롯·툴팁·불필요한 중첩 시트는 지양한다.
5. **실시간 세계 진행:** 탭을 열어도 세계는 계속 움직인다【확정 기획】. 체력/위험 상태 인지, 피격 표시, 닫기·전투 복귀, 모바일 가림/이동 중 조작은 설계·테스트 필요. 피격 시 자동 닫기·무적 부여는 미확정.
6. **기존 세이브/멀티:** UI 이동만으로 `G.equip`, 습득한 스킬·투자 포인트·장착 스킬·`G.treeSeeds` 값을 초기화하지 않는다. 세계 공통 등불나무 성장과 캐릭터 장비/스킬의 저장 주체를 섞지 않는다.
7. **장비/펫/가방과의 연계:** 기존 가방의 장비 카테고리와 '입기/달기', 펫 목록, 스킬/능력 진입을 어떻게 재배치할지 검토한다. 제작/수리/강화는 장비제작대 근처라는 기존 조건을 유지한다.

**기술 검토 요청 항목:** `openPanel('equip')` 라우팅 분리, 기존 `eqRowHTML` 재사용 여부, 반응형 레이아웃, 기존 가방과 캐릭터 화면 간 선택/스크롤 상태, 공격 자동 무기 선택 및 펫 상태 영향, 피격 중 패널 동작, 저장·불러오기 및 멀티 동기화. 사용자 승인 전 게임 코드를 변경하지 않는다.

## HUD 와이어프레임 v1 검토 기록 (2026-10-15) — 【검토 중】

> 사용자 제시 이미지 기반의 **배치 초안과 검토 의견**을 기록한다. 사용자가 최종 승인한 HUD 규칙이 아니며, 이 절은 Claude 구현 지시가 아니다. 이전에 확정된 '모바일 세로 우선·싱글/멀티 메뉴 사용 중 세계 계속 진행·캐릭터 통합 3영역 방향'을 변경하지 않는다.

### 사용자 와이어프레임 v1 — 제안된 화면 역할

- **좌측 상단:** 체력·생존/자원 상태·경험치 등 상태 표시, 효과 아이콘, 눌러서 퀘스트 화면으로 이동하는 '퀘스트 목표' 요약.
- **우측 상단:** 메뉴 / 캐릭터 / 지도 3개 진입 버튼을 세로로 배치. 메뉴는 현재 설정·관리 메뉴에 해당. 캐릭터 화면은 레벨·경험치·능력치·스킬·장비·펫 정보를 포함하도록 제안.
- **캐릭터 화면:** 과거에 합의한 장비 / 스킬 / 세계관 고유 빛·등불(가칭) 3영역과 연결하되, 세 번째 명칭 및 개인 능력 체계는 기존 【검토 중】 상태 유지. 장비·스킬·펫을 사용자에게 보여줄 하위 위치 미확정.
- **하단:** 좌측 조이스틱, 우측 대형 상호작용·공격 버튼과 2×2 스킬 버튼 네 개의 자리, 화면 맨 아래 도구 칸 + 일반 단축칸 다섯 칸 + 가방 진입 아이콘.
- **가방:** 단축칸·가방 아이템·손제작을 한 진입 경로에 구성. 정렬, 가까운 상자로 이동, 버리기 제공 구상.
- **퀘스트:** 메인(현재 '이야기' 퀘스트에 대응하는 표시명 후보) / 도전 퀘스트, 목표 진행도, 완료 및 보상 확인·수령.
- **지도:** 기존 지도 정보에 필터 조작을 제공하려는 구상. 필터 종류와 실제 숨김 규칙은 미확정.
- **월드 피드백:** 캐릭터 바로 위에 떠오르는 알림 배치. 레벨업 UI의 연출 일부를 캐릭터 뒤 레이어로 이동하려는 구상.

### 검토 결과 — 추천안 (아직 미확정)

1. **큰 배치 유지:** 상단 상태·보조 메뉴, 하단 직접 조작·도구/가방의 역할 분리는 유지 권장. HP와 위험 정보의 인지성을 메뉴 열림 상태에서도 확보한다.
2. **스킬 4칸 주의:** 현황 문서상 사용 중인 액티브 스킬은 2칸. 새 초안의 4칸은 단순 배치가 아니라 스킬 시스템 개편으로 이어질 수 있다. 우선 2개 슬롯으로 HUD 테스트하고, 4개를 확정할 때는 스킬 장착/해금·모바일 오입력·터치 영역을 함께 재설계할 것을 추천.
3. **단축칸 5개 표시와 실제 9개 보존:** 현황상 일반 단축칸 9개 + 도구 칸. 와이어프레임처럼 화면에는 5개만 노출하되 나머지를 이용할 수 있도록 페이지/스크롤 방식을 비교. 실제 소지 슬롯을 줄이는 것으로 해석하지 않는다.
4. **자주 하는 행동:** 공격과 상호작용은 둘 다 핵심 버튼. 이동·연속 채집·연속 공격 중 오른손 도달성, 큰 버튼과 스킬 간 손가락 이동, 오입력 및 가림을 검증한다. 상황에 따라 두 버튼 위치가 바뀌는 동적 배치는 추천하지 않는다.
5. **알림 계층화:** 아이템·경험치·회복·피해 수치 같은 짧은 행동 피드백은 캐릭터 주변에, 레시피·지역 발견/퀘스트 완료 등 읽어야 하는 알림은 HUD 별도 영역에. 레벨업의 빛/배경 효과는 캐릭터 뒤, 읽어야 하는 핵심 글자는 앞 또는 머리 위에 놓는 방향 권장. 퀘스트/꾸러미 방향 화살표와의 겹침 확인.
6. **가방 화면 밀도:** '가방'과 '손제작'을 같은 진입 경로 안에서 구분하고, 도구 주머니·단축칸·아이템 상세·버리기의 스크롤/포커스 우선순위를 상세 설계한다. 독립 손제작 버튼의 중복은 정리 가능하나 기존 5종 제작대 접근 조건·재료 규칙을 바꾸지 않는다. '가까운 상자로 이동'은 기존 '상자를 연 상태에서 이동'과 다른 신규 UX이며, 거리 조건·다수 상자·대상 없음·오입력·가득 참·멀티 소유권을 정해야 한다.
7. **퀘스트/지도:** 퀘스트 요약은 항시 한 줄로 억제하고 상세 진행·보상 수령은 퀘스트 안에서 제공한다. '메인' 표시명과 기존 '이야기' 18개를 변경해 혼동을 일으키지 않도록 한다. 지도 필터는 현재 가까이/전체·범례·지역 재료 표시와 연동 검토. 추후 동료 표식·연결 상태를 확장할 수 있게 한다.
8. **세계 실시간 진행:** 【확정 기획】과 같이 모든 메뉴·가방·퀘스트·지도·NPC 창에서도 세계는 진행. 창 열림 중 HP/피격 경고, 빠른 닫기·전투 복귀, 화면 가림을 검증한다. 자동 닫기·무적·창 중 이동 허용은 승인되지 않은 미결정이다.

### 사용자 확인을 기다리는 쟁점 【검토 중】

- 액티브 스킬은 당장 2개 유지인지 4개로 확장하는지(후자는 시스템 변화).
- 보이지 않는 일반 단축칸 4개에 대한 접근: 페이지 / 스크롤 / 별도 가방에서 선택.
- 가방/손제작 탭·고정 단축칸·상자 자동 이동의 상세 조작 및 조건.
- 캐릭터 화면에서 레벨·능력치·스킬·펫의 정확한 서브 IA, 셋째 탭의 명칭과 내용.
- 알림 종류별 우선순위·표시 시간·표시 대상(싱글/멀티), 레벨업 후면 연출 범위.
- 패널 열림 중 피격 인지·창 복귀 방식, 지도 필터 및 퀘스트 화면 상세 IA.

### 구현 때 볼 것 (기술 메모)
- 머리 위 막대는 지금 HTML HUD가 아니라 세계(캔버스) 쪽에 그려야 해요. 멀티플레이 때 친구 머리 위에도 보일지는 따로 정해요.
- 단축칸 숫자 키 1~9(PC)·「새 물건은 빈 단축칸부터」(v65) 규칙은 그대로이고, 폰에서 안 보이는 6~9칸에 물건이 들어가면 넘기기 버튼에 표시가 필요할 수 있어요.
- 창 열림 중 세계 진행(【확정 기획】 B안)과 같이 구현해야 「창 그대로 + 경고」가 의미가 있어요.
- 빨간 점 「처음 얻은 물건」은 **본 적 있는 물건 목록을 새로 저장**해야 해요(캐릭터 것, `CHAR_KEYS`). 옛 세이브는 지금 가진 물건을 모두 「본 것」으로 시작해서 점이 한꺼번에 뜨지 않게.
- 조이스틱 고정은 지금 `ui/input.js`의 「테두리 밖으로 끌면 받침이 35%씩 따라옴」을 없애는 작은 변경이라, HUD 재설계와 따로 먼저 만들 수도 있어요(조작감이 바뀌므로 버전 번호를 받아서).
- C 키가 제작 → 캐릭터로 바뀌는 건 제작이 가방 안으로 들어갈 때 같이 바꿔야 해요(따로 바꾸면 C로 제작을 못 열게 됨).
