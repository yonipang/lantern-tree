# 기획 결정사항 및 작업 우선순위

- 마지막 갱신: 2026-10-14
- 목적: 변경 가능한 제안과 사용자에게 승인받은 결정을 구분한다.
- 상세 설계는 개별 문서를 우선하고, 이 문서에는 결정과 주요 쟁점만 남긴다.

## 현재 진행 우선순위

1. **【확정 기획】 모바일 세로 화면 중심 UI/UX의 **기획·설계**가 우선.** 전체 IA → HUD → 주요 기능 화면 → 인터랙션 규칙을 검토한다. 이는 **UI 코드 구현을 멀티플레이보다 먼저 진행하겠다는 결정은 아니다.**
2. **【확정 기획】 스토리·NPC는 전체 UI를 설계할 수 있을 정도의 기본 요구사항만 우선 반영한다.** 상세 스토리 및 NPC 구성과 실제 구현은 UI/UX 기초 설계 이후 진행한다.
3. **【보류】 스토리 시스템·NPC의 구현** — 향후 사용자가 별도로 구현을 요청해야 한다.
4. **【검토 중】 UI 코드 구현 시점과 멀티플레이 개발 순서** — 현재 `dev/PLAN.md`는 12~15단계 멀티플레이 구현을 다음 작업으로 지정한다. 화면 파일 변경 충돌을 피하기 위한 권장안은 'UI/UX 설계는 지금 진행 → 멀티플레이 구현·안정화 → 확정된 UI 코드 구현'이며 사용자 확정 전에는 기존 개발 계획을 임의 변경하지 않는다.

## 멀티플레이 연계 기획의 미결정 사항 (2026-10-14)

멀티플레이 방식 자체와 개발 단계는 `dev/PLAN.md`를 따른다. **방장 계산·저장, 각자 캐릭터 저장, 2~4명으로 시작, 개발 12→13→14→15단계**는 기존에 정한 방향이며 ChatGPT가 변경하지 않는다. 아래는 향후 사용자 승인이 필요한 항목이다.

| 중요도 | 결정 대상 | 현재 상태 | 관련 설계 문서 |
|---|---|---|---|
| 확정 | **싱글·멀티 모두 플레이 중 메뉴를 열어도 세계 계속 진행(B안)** | 【확정 기획 · 2026-10-14】 | `UIUX-재설계.md` |
| 높음 | 멀티 창 사용 중 피격·위험 알림, 창 닫기·이동·방어와의 양립 방식 | 【검토 중】 | `UIUX-재설계.md` |
| 높음 | 퀘스트의 세계 공동 진행 / 개인별 진행 / 혼합형 방식 | 【검토 중】 | `세계관-NPC.md` |
| 높음 | 공동 퀘스트의 **보상 각자 수령 여부**, 참여·기여 조건, 중복 수령 방지 | 【검토 중】 | `세계관-NPC.md` |
| 높음 | NPC 대화 진행·선택지 기록·호감도(도입한다면)를 **세계 공통/캐릭터 소유/세계 안 플레이어별** 중 어디에 둘지 | 【검토 중】 | `세계관-NPC.md` |
| 보통 | 보스 처치·퀘스트·NPC 사건을 **누구에게 알릴지**와 알림 강도 | 【검토 중】 | `UIUX-재설계.md` |
| 추후 | 정확한 최대 인원, WebRTC 연결 서비스, 방장 이탈 시 세션 처리, 동료가 방장 세계에서 얻은 아이템의 귀속·이동 규칙 | 【검토 중】 | `dev/PLAN.md` 확인; 결정 전 변경 금지 |

**확인된 영향:**
- 현재 한 명이 퀘스트 보상을 받으면 공유 세계의 다른 사람은 같은 보상을 별도로 받을 수 없고, 학습한 레시피는 그 캐릭터에 저장된다.
- **싱글플레이와 멀티플레이 모두** 개인의 메뉴·NPC 대화창 때문에 세계가 정지되어서는 안 된다. 현재 패널은 게임을 정지시키므로 향후 UI 구현 변경이 필요하다. 구현 완료로 표시하지 않는다.
- 화면 진입·참가자·지도 동료 위치·연결 문제 UI는 전체 IA 단계에서 수용 공간을 계획한다.
- 기존 이야기 퀘스트 순서·조건·보상 ID 변경은 세이브 진행 재계산 및 중복 지급 위험을 검토한다.

## 현재 구현과 구분해야 할 점

- 기존 게임에는 5개 지역·5종 보스·등불나무/빛씨앗 성장·**이야기/도전 퀘스트** 등이 있다. **이는 코드·현황 문서 기준의 구현 사실이지 새 기획의 확정 사항이 아니다.**
- 현재 퀘스트를 전면 개편하는 것은 기술적으로 가능하나 보스 드롭, 해금, 엔딩, 저장 데이터 등 다른 기능과의 의존성 검토가 필요하다. **특히 이야기 퀘스트 진행 단계는 불러올 때 조건을 처음부터 다시 확인하여 계산한다**(`save/state.js`, `sim/quests.js`). 퀘스트 순서·조건을 바꾸면 구 세이브의 진행도가 새 조건으로 계산되고, 이미 받은 보상의 **퀘스트 ID를 바꾸면 중복 수령 위험**이 있다. 재설계 시 세이브 이행 및 보상 중복 방지를 기술 검토해야 한다.
- NPC 및 상세 스토리 시스템은 현재 현황 문서에서 【미구현】으로 정리되어 있다. 변경 시 반드시 최신 코드로 재확인한다.
- 코드·검증 결과의 원본은 `dev/src/` 및 `dev/design/등불나무-최신게임현황.md`이다.
