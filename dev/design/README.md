**모든 파일의 실제 위치는 `dev/design/` 바로 아래이다.** 같은 문서를 다른 폴더에 중복 보관하지 않는다. 새 주제가 구체화될 때만 주제 문서를 추가한다(예: `건축모드.md`, `바닥파기.md`). 날짜별 문서와 중복 사본을 만들지 않는다.

**기획 문서와 현황 문서는 따로 둔다.** 기획 문서 = 앞으로 어떻게 할지(사용자 승인 기준), 현황 문서 = 지금 코드가 실제로 어떤지(코드·테스트 기준). 둘을 섞어 적지 않는다.

## 기획 작업 순서 (Claude)

사용자가 새 기능·규칙·UI·스토리·밸런스를 이야기하거나 「기획하자」고 하면:

1. **지금 상태 확인**: 현황 문서의 관련 부분, `기획-결정사항.md`, 관련 주제 문서, 필요하면 `dev/src/` 코드와 `dev/PLAN.md`. 예전 대화의 기억을 최신으로 보지 않는다. 기획 가이드의 핵심 철학(탐험·전투·건축의 연결, 스스로 찾는 목표)과 맞는지 본다.
2. **정할 것 목록 만들기**: 무엇을 정해야 하는지(규칙·수치·조작·화면·저장 범위·멀티 영향·옛 세이브)를 쉬운 말로 나눈다.
3. **선택지 제안**: 항목마다 2~3개 안과 **추천안 + 이유**, 각 안의 장단점과 만들기 어려운 정도(코드·세이브·테스트 영향)를 함께 말한다. 화면·그림이 걸리면 미리보기(그림 아닌 배치 가이드)를 보여 줄 수 있다.
4. **사용자가 고른 것만 확정**: 사용자가 명시적으로 고르거나 「좋아」라고 한 항목만 【확정 기획】으로 적는다. 대답하지 않은 항목·Claude의 추천은 【검토 중】으로 남긴다. 「알아서 정해」라고 맡기면 Claude가 정하되 무엇을 정했는지 목록으로 보여 주고 확인받는다.
5. **문서에 기록**: 같은 작업에서 `기획-결정사항.md`(결정 표에 날짜·내용 한 줄, 미정 표 갱신)와 주제 문서를 고친다. 오래된 문구가 새 결정과 충돌하면 본문을 고치고 변경 기록을 남긴다.
6. **저장소에 올리기**: 기획 문서만 바뀐 것은 브랜치 → PR → main 합치기로 올린다(게임 동작 변화 없음이라 버전 번호 없음, 버전 기록에 「문서」 한 줄). 비교·전체 테스트는 필요 없고 `python3 dev/build.py`만 확인한다.
7. **구현은 따로**: 기획을 확정했다고 바로 코드를 고치지 않는다. 사용자가 구현을 요청하면(보통 새 대화에서) 버전 번호를 받아 구현한다. 확정 기획만 구현 대상이고 【검토 중】·【보류】는 구현 요구가 아니다.

### 기획할 때 지킬 것

- 새 게임 규칙·밸런스 수치·퀘스트·보상·해금 조건은 **사용자 승인 없이 확정하지 않는다.** Claude가 기획을 맡아도 최종 결정은 사용자다.
- 수치를 제안할 때는 지금 수치(현황 문서·코드)와 바뀐 뒤를 나란히 보여 주고, 진행 속도·난이도에 미치는 영향을 말한다.
- 퀘스트·해금을 바꾸면 선행 조건, 이미 달성한 세이브, 보상 중복 수령을 함께 검토한다.
- 기획 가이드(`등불나무-상세게임기획가이드.md`)는 사용자가 수정을 승인할 때만 고친다.
- 그림: 2026-10-19부터 **필요한 그림은 지금 게임 그림을 참고해 Claude가 임시로 그린다**(사용자 요청). 사용자가 나중에 손그림으로 바꿀 수 있게 `dev/art/` 파일 자리를 지킨다. 기획에는 필요한 그림 목록·크기·용도를 적는다.
- 멀티플레이 개발 단계 중에는 혼자 할 때의 동작·밸런스를 바꾸는 기획을 확정해도 구현은 멀티 단계와 겹치지 않게 순서를 따로 정한다.

## 멀티플레이를 고려한 기획 검토 규칙

UI/UX·스토리·NPC·퀘스트·콘텐츠를 설계할 때는 **멀티플레이를 추후 덧붙일 기능이 아닌 기본 설계 제약**으로 취급한다. 확정된 방식과 실제 구현 상태는 매번 `dev/PLAN.md`·최신 코드로 확인한다.

1. **세계 시간과 창 【확정 기획 · 2026-10-14】: 싱글플레이와 멀티플레이 모두 플레이 중 가방·제작·지도·퀘스트·설정 등 메뉴나 NPC 대화창을 열어도 세계 시간·몬스터 행동·다른 플레이어의 행동은 계속 진행된다.** 창을 열었다는 이유로 게임을 일시정지시키지 않는다. 창이 열려 있을 때 피격 인지, 빠른 닫기·복귀, 세계 시야 확보와 모바일 조작 부담을 설계한다. 피격 시 자동 닫기·무적·이동 허용 방식 등 세부 UX는 아직 【검토 중】이다. 이는 기획 규칙이며 현재 코드에 구현됐다는 뜻은 아니다.
2. **상태 소유권:** 새로운 NPC·퀘스트·관계·보상·해금 데이터를 설계할 때 **세계 공통 / 캐릭터 소유 / 세계 안 플레이어별** 중 저장·공유 범위를 명시한다. 퀘스트 진행의 공유 여부와 보상의 수령 주체는 **별개 항목**으로 검토한다.
3. **피드백 대상:** 알림·소리·진행 표시마다 **행동한 플레이어만 / 관련 동료 / 세계 전체** 중 누가 받아야 하는지 구분한다. 현재의 로컬 이벤트 처리와 향후 동료 알림 설계를 혼동하지 않는다.
4. **멀티플레이 진입·상태 UI:** 방 생성·방 코드 입장, 참가자 표시, 지도상 동료 위치, 연결 끊김·재접속·방장 이탈 안내를 전체 IA에 미리 고려한다. 배치·형태와 미확정 처리 규칙은 사용자 결정 전까지 확정하지 않는다.
5. **기존 퀘스트·세이브 호환:** 이야기 퀘스트 순서·조건을 바꾸면 기존 세계 진행이 재계산될 수 있고, 보상 식별자 변경은 중복 수령 위험이 있다. 빛씨앗·보스·엔딩·해금의 영향까지 검토한다.
6. **의사결정:** 동작·저장 범위·보상 분배 등 미정인 항목은 관련 기획 문서 및 `기획-결정사항.md`에 **【검토 중】**으로 기록한 뒤 사용자에게 질문한다. 승인 없이 기본값을 확정하지 않는다.
7. **개발 순서 분리:** `dev/PLAN.md`와 `CLAUDE.md`의 멀티플레이 12~15단계 및 '다음 단계' 실행 순서는 기획 작업 중에 바꾸지 않는다(바꾸려면 사용자 승인). 이 규칙은 **기획 검토 기준**이지 즉시 코드 구현 지시가 아니다.

세부 UX는 `UIUX-재설계.md`, NPC·서사·퀘스트의 공유 범위는 `세계관-NPC.md`, 미결정 목록은 `기획-결정사항.md`에서 관리한다.

## 기획과 구현의 작업 순서 (2026-10-14)

- **【확정 기획】** UI/UX **설계**(IA·HUD·화면·상호작용 정의)를 스토리/NPC 상세 기획보다 우선한다.
- **【검토 중 — 추천】** UI/UX의 **코드 구현**은 기존 `dev/PLAN.md`의 멀티플레이 12~15단계와 같은 화면 파일을 동시에 수정하지 않도록 별도 단계로 관리한다. 권장안은 **UI/UX 설계를 먼저 진행하는 동안 개발은 멀티플레이 계획을 유지하고, 멀티플레이 단계가 안정화된 뒤 승인된 UI 코드를 구현**하는 방식이다.
- 실제 코드 구현의 우선순위 변경은 **사용자 승인 후** `dev/PLAN.md`·`CLAUDE.md`의 실행 순서에도 반영한다. 이 폴더의 기획 문서만으로 Claude의 '다음 단계'가 바뀌지 않는다.
- 동시 작업이 필요하면 서로 겹치지 않는 파일·브랜치·합치는 순서를 사전에 합의한다.

## 협업 흐름

1. **기획:** 사용자와 Claude가 주제를 이야기한다. Claude가 정할 것·선택지·추천안을 내고, 결정 전 내용은 【검토 중】으로 기록한다.
2. **확정:** 사용자가 승인한 부분만 【확정 기획】으로 올리고 `기획-결정사항.md`에 날짜·변경 내용을 기록한다.
3. **구현 요청:** 사용자가 개발을 요청하면 Claude가 코드를 고치고 테스트·배포한다.
4. **동기화:** 구현 뒤 현황 문서를 코드 기준으로 갱신하고, 기획 문서의 해당 항목에 「구현됨 vNN」을 적는다.
5. **변경:** 만들다 보니 기획을 바꿔야 하면 코드를 고치기 전에 사용자에게 문제와 대안을 말하고, 승인 뒤 기획 문서에 반영한다.

### 충돌 시 판단 기준

- 실제 구현: **코드 및 테스트 > 구현 현황 문서 > 기획 문서의 묘사**
- 앞으로의 설계: **사용자의 최신 명시적 승인 > 이 폴더의 확정 기획 > 검토 중인 제안**
- 상위 게임 철학: `등불나무-상세게임기획가이드.md`. 충돌하면 사용자에게 먼저 확인한다.

## 문서 내 상태 표기

- **【확정 기획】** 사용자가 결정한 방향·규칙. 실제 구현 완료를 뜻하지 않는다.
- **【검토 중】** 아직 채택하지 않은 아이디어·설계안 (Claude의 추천 포함).
- **【보류】** 판단이나 작업을 일부러 미룸.
- **【구현】** 실제 게임 코드를 확인해 동작을 설명한 경우에만 사용. 최종 기준은 소스 코드와 테스트.
- **【확인 필요】** 코드·수치·규칙에 대해 추가 확인이 필요한 경우.

> GitHub 저장소의 이 폴더가 기획 원본이다. claude.ai 프로젝트에는 버전 기록만 두고, 기획 문서 사본을 올리지 않는다.
