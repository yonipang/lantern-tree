## 기획 작업 전 필수 확인

ChatGPT는 새로운 시스템·UI·스토리·밸런스 기획을 시작하거나 기존 기획을 변경하기 전에 **매번 GitHub 최신 상태**를 확인한다.

1. `dev/design/등불나무-최신게임현황.md` — Claude가 유지하는 실제 구현·기능·수치·UI 현황.
2. `dev/design/기획-결정사항.md` — 최신 승인 사항과 우선순위.
3. 기획에 직접 관련되는 `dev/src/` 코드 — 문서에 없는 규칙·구현 상태·기술적 제약을 확인할 필요가 있을 때.
4. 진행 단계·코드 작업 일정에 영향이 있다면 `dev/PLAN.md`도 확인한다.

현황 문서는 매번 새로 조회하고 예전 대화의 수치나 구현 상황을 최신으로 간주하지 않는다. 코드와 현황 문서가 다르면 코드를 근거로 차이를 명시하되, **Claude 담당 현황 문서를 ChatGPT가 직접 수정하지 않는다**.

## 기획 문서 최신 상태 유지

ChatGPT는 기획 작업을 수행할 때마다 이 폴더의 관련 문서를 **현재 대화에서 승인·수정된 내용과 일치하도록 관리**한다.

1. 사용자가 기획 방향·우선순위·규칙을 새로 확정하거나 변경하면, 같은 작업에서 `기획-결정사항.md`와 관련 주제별 문서를 함께 갱신한다.
2. 아직 논의 중인 제안은 【검토 중】으로만 기록하고, 사용자의 명시적 승인 없이 【확정 기획】으로 승격하지 않는다.
3. 새 결정이 과거 기획과 충돌하면 오래된 문구를 남겨 혼란을 만들지 않고, 최신 승인 내용을 본문에 반영하며 변경 이력을 남긴다.
4. 이미 Claude가 구현한 내용과 기획을 비교할 때는 위 「기획 작업 전 필수 확인」에 따라 최신 현황·관련 코드를 재확인한다. 실제 구현 기록은 Claude 담당 문서를 수정하지 않고, 기획 문서의 영향 사항만 갱신한다.
5. GitHub 수정이 실패하거나 충돌하면 문서를 갱신했다고 주장하지 않고 사용자에게 실패와 미반영 사항을 보고한다.
6. **자동·상시 감시 또는 백그라운드 업데이트는 하지 않는다.** 사용자가 대화를 통해 기획 작업을 진행할 때 최신 상태를 확인하고 필요한 문서 수정까지 처리한다.

### 파일 수정 경계

- **ChatGPT:** 이 폴더(`dev/design/`)의 기획 문서(이 `README.md`, `기획-결정사항.md`, 주제별 기획 문서)만 수정한다. 같은 폴더의 `등불나무-최신게임현황.md`(Claude 담당)·`등불나무-Claude-Code-작업지침.md`·`등불나무-상세게임기획가이드.md`(사용자 승인 없이는 읽기 전용)는 수정하지 않는다. 사용자에게 요청받지 않은 게임 코드·테스트·`CLAUDE.md`·`dev/PLAN.md`·구현 현황 문서는 수정하지 않는다.
- **Claude:** 이 폴더의 기획 문서는 구현할 기획을 읽는 용도다. 기획이 불분명하거나 구현이 어렵다면 변경하지 말고 의견을 제시한다. 구현 현황은 종전의 `등불나무-최신게임현황.md`에서 관리한다.
- 기존 상위 원칙 `dev/design/등불나무-상세게임기획가이드.md`는 사용자가 수정 승인하지 않는 한 읽기 전용이다.

## 문서 내 상태 표기

- **【확정 기획】** 사용자가 의사결정한 방향·규칙. 단, 실제 구현 완료를 의미하지 않는다.
- **【검토 중】** 아직 채택하지 않은 아이디어·설계안.
- **【보류】** 판단이나 작업을 의도적으로 미룸.
- **【구현】** 실제 게임 코드를 확인하여 동작을 설명한 경우에만 사용. 구현 현황의 최종 기준은 소스코드와 테스트.
- **【확인 필요】** 코드·수치·규칙에 대해 추가 확인이 필요한 경우.

## 멀티플레이를 고려한 기획 검토 규칙

UI/UX·스토리·NPC·퀘스트·콘텐츠를 설계할 때는 **멀티플레이를 추후 덧붙일 기능이 아닌 기본 설계 제약**으로 취급한다. 확정된 방식과 실제 구현 상태는 매번 `dev/PLAN.md`·최신 코드로 확인한다.

1. **세계 시간과 창:** 멀티플레이에서는 한 사람이 가방·제작·지도·퀘스트·NPC 대화창을 열어도 공유 세계는 계속 진행된다. 창이 열려 있을 때의 피격 인지, 안전한 닫기, 세계 시야 확보를 설계한다. **싱글플레이에서 창을 열었을 때 일시정지할지는 【검토 중】**이며 임의 확정하지 않는다.
2. **상태 소유권:** 새로운 NPC·퀘스트·관계·보상·해금 데이터를 설계할 때 **세계 공통 / 캐릭터 소유 / 세계 안 플레이어별** 중 저장·공유 범위를 명시한다. 퀘스트 진행의 공유 여부와 보상의 수령 주체는 **별개 항목**으로 검토한다.
3. **피드백 대상:** 알림·소리·진행 표시마다 **행동한 플레이어만 / 관련 동료 / 세계 전체** 중 누가 받아야 하는지 구분한다. 현재의 로컬 이벤트 처리와 향후 동료 알림 설계를 혼동하지 않는다.
4. **멀티플레이 진입·상태 UI:** 방 생성·방 코드 입장, 참가자 표시, 지도상 동료 위치, 연결 끊김·재접속·방장 이탈 안내를 전체 IA에 미리 고려한다. 배치·형태와 미확정 처리 규칙은 사용자 결정 전까지 확정하지 않는다.
5. **기존 퀘스트·세이브 호환:** 이야기 퀘스트 순서·조건을 바꾸면 기존 세계 진행이 재계산될 수 있고, 보상 식별자 변경은 중복 수령 위험이 있다. 빛씨앗·보스·엔딩·해금의 영향까지 검토한다.
6. **의사결정:** 동작·저장 범위·보상 분배 등 미정인 항목은 관련 기획 문서 및 `기획-결정사항.md`에 **【검토 중】**으로 기록한 뒤 사용자에게 질문한다. 승인 없이 기본값을 확정하지 않는다.
7. **개발 순서 분리:** `dev/PLAN.md`와 `CLAUDE.md`의 멀티플레이 12~15단계 및 '다음 단계' 실행 순서는 ChatGPT가 수정하지 않는다. 이 규칙은 **기획 검토 기준**이지 즉시 코드 구현 지시가 아니다.

세부 UX는 `UIUX-재설계.md`, NPC·서사·퀘스트의 공유 범위는 `세계관-NPC.md`, 미결정 목록은 `기획-결정사항.md`에서 관리한다.

## 기획과 구현의 작업 순서 (2026-10-14)

- **【확정 기획】** UI/UX **설계**(IA·HUD·화면·상호작용 정의)를 스토리/NPC 상세 기획보다 우선한다.
- **【검토 중 — 추천】** UI/UX의 **코드 구현**은 기존 `dev/PLAN.md`의 멀티플레이 12~15단계와 같은 화면 파일을 동시에 수정하지 않도록 별도 단계로 관리한다. 권장안은 **ChatGPT가 UI/UX 설계를 먼저 진행하는 동안 Claude는 멀티플레이 개발 계획을 유지하고, 멀티플레이 단계가 안정화된 뒤 승인된 UI 코드를 구현**하는 방식이다.
- 실제 코드 구현의 우선순위 변경은 **사용자 승인 후** `dev/PLAN.md`·`CLAUDE.md`의 실행 순서에도 반영한다. 이 폴더의 기획 문서만으로 Claude의 '다음 단계'가 바뀌지 않는다.
- 동시 작업이 필요하면 서로 겹치지 않는 파일·브랜치·합치는 순서를 사전에 합의한다.

## 협업 흐름

1. **기획:** 사용자가 ChatGPT와 주제를 검토한다. 대안과 장단점은 【검토 중】으로 기록한다.
2. **확정:** 사용자가 승인한 부분만 【확정 기획】으로 승격하고 `기획-결정사항.md`에 날짜·변경 내용을 기록한다.
3. **기술 검토:** Claude는 확정 기획을 읽고 구현 가능성, 코드·세이브·테스트 영향, 애매한 점을 반환한다.
4. **구현 요청:** 사용자가 개발을 요청하면 Claude가 코드를 변경·테스트한다. ChatGPT는 임의로 구현하지 않는다.
5. **동기화:** Claude는 실제 코드 기준으로 현황 문서를 갱신한다. ChatGPT는 다음 기획에서 최신 코드·현황을 확인한다.
6. **변경 요청:** 구현 제약으로 기획을 수정해야 한다면 사용자 승인 후 기획 문서에 반영한다. Claude가 기획을 임의 확정하지 않는다.

### 충돌 시 판단 기준

- 실제 구현: **코드 및 테스트 > 구현 현황 문서 > 다른 기획 문서의 묘사**
- 앞으로의 설계: **사용자의 최신 명시적 승인 > 이 폴더의 확정 기획 > 검토 중인 제안**
- 상위 게임 철학: `dev/design/등불나무-상세게임기획가이드.md` 참조. 충돌하면 사용자에게 먼저 확인한다.

## Claude에 인계할 때

1. 이 `README.md`를 먼저 읽고 관련 기획 문서를 확인한다.
2. 【확정 기획】과 【검토 중】을 구별한다. 【검토 중】은 구현 요구사항이 아니다.
3. 실제 코드·저장 데이터·플랫폼 제약과 충돌하는 부분만 구체적으로 보고한다.
4. 사용자가 해당 구현을 요청하기 전에는 기획을 읽었다는 이유만으로 게임 코드를 변경하지 않는다.

> **중요:** GitHub 저장소의 이 폴더는 기획 원본이다. Claude 웹 프로젝트의 `plans/` 등으로 복사한다면 사본으로 취급하고 GitHub 원본을 우선한다. 이 원본과 Claude 프로젝트 사본이 자동 동기화되는 것은 아니다.
