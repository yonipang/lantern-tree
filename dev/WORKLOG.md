# 작업 기록 (Claude 세션용)

새 세션이 「지금까지 무슨 일이 있었고, 무엇이 정해졌는지」를 빨리 알 수 있게 적어 둬요. 규칙은 `CLAUDE.md`, 계획은 `dev/PLAN.md`, 작업 순서는 `dev/README.md`.
날짜별로 위에 새로 덧붙여요.

## 사용자와 일하는 방식

- 사용자는 개발자가 아니에요. **쉬운 한국어**로, 전문 용어는 풀어서 설명해요.
- 사용자가 직접 올리는 건 **그림(`dev/art/`)뿐**이에요. 게임 코드는 Claude 세션이 고쳐서 올려요.
  - 올리는 순서: 브랜치에서 작업 → PR 만들기 → 합치기(merge).
  - `main`에 들어가면 자동 배포(`deploy.yml`)가 테스트를 돌리고 배포해요. 약 5~10분 뒤 Actions 결과를 확인해 짧게 알려 줘요.
- **게임 동작이 바뀔 수 있으면 먼저 알리고 결정을 받아요.** 결정할 게 있으면 추천안과 이유를 같이 드려요. 사용자가 질문 창을 닫은 적이 있어서, 질문은 글로 써도 괜찮아요.
- 작업이 끝나면 테스트 결과(통과 개수, 걸린 시간)를 숫자로 보고해요.

### 배운 것 (같은 실수 막기)

- 테스트 페이지는 `file://`이 아니라 작은 웹 서버(`harness.URL`)로 열어요. `file://`에서는 바쁠 때 localStorage가 사라져 저장 테스트가 가끔 실패했어요.
- 테스트마다 **새 세계가 무작위**예요. 지도 모양(바위·물 위치)에 기대지 말고, 어떤 세계에서도 맞게 확인하거나 필요한 칸을 직접 만들어요. 드문 세계 예시(시드): 원래 지도 150461, 523057148 / 고리 지도 63352, 115292.
- 기다림은 실제 시간이 아니라 게임 시간(`wait_game`)·조건(`wait_until`)으로 해요. 상태 맞추기와 확인은 한 번의 `ev` 안에서 해요.
- 「자연 바위」 판정은 `naturalWalls()`(처음 만들어진 세계를 시드로 다시 만들어 캐시)와 `shutsIn()`이 해요 (`features/deep-survival.js`). 고리 지도에서 처음 한 번 약 0.15초가 걸려서, `closedIn`은 바위까지 막힘으로 먼저 보고 막혔을 때만 이걸 불러요.
- 파이썬 테스트 코드 줄 중간에 `#` 주석을 넣으면 뒤의 코드가 주석이 돼요 (한 번 테스트가 조용히 망가졌어요). 주석은 줄 끝이나 따로 한 줄에.
- 고친 뒤에는 **옛 코드에서는 실패하고 새 코드에서는 통과하는지** 확인해요 (`git stash`로 게임 코드만 되돌려 테스트를 돌려 봄).
